# Architecture

Where things live and how to test them. The spec is issue #26; terms follow `GLOSSARY.md`.

## The four parts

```
 toolbar icon / Alt+Shift+L
          │ action.onClicked
          ▼
 ┌──────────────────┐ start-session / stop-session ┌──────────────────────────┐
 │ service worker   │─────────────────────────────▶│ offscreen document       │
 │ (thin router)    │                              │ owns the session         │
 └──────────────────┘                              └──────────────────────────┘
   │ scripting.executeScript                         ▲ caption        │ session-event
   ▼ (activeTab grant)                               │ PCM (port)     ▼
 ┌──────────────────┐                                │      ┌──────────────────┐
 │ caption reader + │────────────────────────────────┘      │ side panel       │
 │ audio capture    │                                       │ (display only)   │
 │ (in the tab)     │                                       │                  │
 └──────────────────┘          stop-listening ◀─────────────└──────────────────┘
```

| Part | File | Job |

| Service worker | `src/entrypoints/background.ts` | Icon click / Alt+Shift+L (bound to `_execute_action`, so both run `action.onClicked`). Glue only. |

## The session (seam 1)

`createSession(deps)` returns `{ dispatch(input), subscribe(listener), snapshot() }`.

- **Inputs** (`SessionInput` in `src/session/types.ts`): `start` (with `settings`: mode and API key; a blank key stops at once with `no-key` and nothing is sent; local mode without a `LanguageModel`, or with Nano not `available`, stops with `local-model-unavailable`, never switching to cloud; and the page context: title, channel, description and `recordedOn`, which sets the judged-as-of date), `caption`, `on-device-segment` (speech-to-text of the tab's audio), `speech-to-text` (seconds of audio speech-to-text ran on, for the footer's counters), `audio` (whether it is flowing), `audio-capture` (how the tab's audio is captured: the page's player, tabCapture, or a blocked player and why; a blocked report is ignored while tabCapture runs, and the page's audio flowing again drops one), the audio inputs (`on-device-segment`, `speech-to-text`, `audio`, `voices`) saying which source they came from (`from`: `page`, the default, or `tab`; while tabCapture runs the page's are ignored), `force-check` (the viewer's "Check this" on a line), `speaker-answer` (the viewer's answer to "Who said this?" on a card; after Stop too, when it re-checks the card without listening again), `voices` (voice separation's turns for a stretch of audio, voices it merged, or `failed`), `voice-name` and `voice-skip` (the answer to "Who is this?"; after Stop too), `separate-voices` ("Tell voices apart for this video"; offered and taken only while listening), `settings-withdrawn` (Forget key or a mode switch after Stop: nothing more is sent with the old settings, and prompts close), `stop`, `source-opened` (the viewer opened a source's link; accepted after Stop too, ignored unless a card shows that link), `page` (a new page on the same site: later checks use its context, and cue de-duplication and the transcript switch's caption times start again), `clear` (Clear now). Later tickets add more page context and other viewer commands as more `SessionInput` variants.
- **Outputs**: `SessionEvent`s: `started`, `line`, `line-skipped` (breakdown's skipped parts, on the sentence's first line), `card` (the whole card, upserted by id), `card-removed` (a sentence that held no claim), `transcript-source` (captions or the on-device transcript; `SessionView.transcriptSource`), `audio-capture` (`SessionView.audioCapture`; a new page drops a blocked player, tabCapture carries on), `stopped`, `source-opened` (the view's `opened` list: links marked "opened" for the rest of the session), `page`, `cleared` (the transcript, cards, opened marks and voices are gone), `line-voice` (a caption line's voice, once its audio is separated), `voice` (`SessionView.voices`: first heard, named, skipped or merged), `voice-separation` (`SessionView.voiceSeparation`), `counters` (`SessionView.counters`, the whole `SessionCounters` each time; see "Cost and footprint footer"). Speaker prompts ride on the card (`Card.whoSaid`, `Card.speaker`). `settled()` resolves once no check is in flight: after `stop`, checks already running still emit their `card` events up to a label. Each carries `sessionId` and a gap-free `seq`. `snapshot()` equals `applyEvent` folded over every event (`src/session/view.ts`), so add each new event to `applyEvent` and the panel gets it for free.
- **Dependencies** (`SessionDeps`) are injected: a `Clock`, `fetch` (the provider's LLM and search, nothing else), `ratings`, the source-ratings data (defaults to the bundled MBFC snapshot; tests pass `fakeRatings()` from `src/session/testing/fake-ratings.ts`), the `ClaimFilter` (optional: without one every sentence goes to breakdown), `languageModel`, Chrome's `LanguageModel` (Gemini Nano) for local mode, and `separatesVoices` (voice separation can run here; without it voices are never told apart and never offered). Put each test fake in `src/session/testing/`: `fake-clock.ts`; `fake-venice.ts`, a fake `fetch` that speaks Venice's wire format and records every request; `fake-filter.ts`, which by default passes sentences with a digit in them; and `fake-language-model.ts`, which answers by the response schema's shape, crashes (`kErrorUnknown`) or hangs on request, crashes on a follow-up prompt as Nano does, loses every session when it crashes (so only a rebuilt one answers), and records every session (created or cloned) with its prompts for counting.

**Transcript source** (`transcript-source.ts`). Captions are preferred. While they come, on-device segments are held back (the last 30 s). If no caption arrives for `TAKE_OVER_MS` (10 s) of flowing audio, the on-device transcript takes over: the held segments after the last caption become lines, then each new one does, tagged `on-device`. A piece of audio that began before the captions ended drops its first words where they repeat the captions' last words (when nothing lines up it is kept whole: better twice than never). The next caption switches back at once. Time without audio (paused, silent) doesn't count, so pausing a captioned video doesn't switch. A pause of up to 10 s holds the time already counted (speech with 3 s pauses, which stop "audio flowing" for a moment, still switches after about 10 s of it); a caption or a longer pause starts the count again. On-device lines go through sentences, the filter and the checks like captions.

Tests (`src/session/capture.test.ts` for how audio is captured, `src/session/session.test.ts` for the transcript, `src/session/transcript-source.test.ts` for the caption / on-device switch, `src/session/checks.test.ts` for checks, `src/session/sources.test.ts` for source handling, `src/session/claim-filter.test.ts` for the filter and forced checks, `src/session/lifecycle.test.ts` for Stop settling, Clear now, a new page and the Save session export, `src/session/local-mode.test.ts` for Nano, `src/session/speaker.test.ts` for who said it, `src/session/voices.test.ts` for voice separation and "Who is this?", `src/session/joint-session.test.ts` for self-contained claims, the date said, the claim review and one card per claim, on a fixture from a real run: `testing/joint-session-2025.ts`) drive `dispatch` and assert only on emitted events and snapshots, and on the fake provider's recorded requests: what the viewer would see or what would leave the device. They never check internal calls or prompt wording.

### Checks: one stage per file (`src/session/checks/`)

Transcript lines become sentences, and each sentence runs through the stages. Each stage is its own file, so tickets extend one stage without touching the others:

| Step | File | Job | Extended by |
|---|---|---|---|
| Sentences | `sentences.ts` | Cues → sentences (split on `.?!` but not after an initial or abbreviation like "H. RES.", joined across cues such as House roll-up lines, flushed after 4 s without one; times are the readers' already lag-shifted ones), each with ~30 s of earlier transcript as context | #33/#34 |
| 0. Claim filter | `filter.ts` | The on-device `ClaimFilter`: a dropped sentence becomes a skipped line with the generic reason "not flagged as a claim" and is never sent anywhere. If the model can't run, the sentence passes | #41 (threshold) |
| 1. Breakdown | `breakdown.ts` | Sentence + context + title/channel (+ the description, only for an on-device model: `JsonModel.onDevice`) + the day it was said (the judged-as-of date, marked when the page gives none) + any known speaker (the viewer's, a named voice's, or the one person the page names) → claims, each rewritten to stand alone (who and what its words refer to named from the context, page or date, never from anyone's views; time words as years counted from the day said), with the words it couldn't resolve (`unresolved`), implied claim, `premiseOf`, whether it depends on the speaker, the words that refer to them and the speaker if the given speaker or the title and channel settle it, queries `fact` and `claim`; skipped parts with a reason; and `people_named` (everyone the title and channel name). | 1a. Code checks | `tidy.ts` | No model. | 1a′. The answer counts only if those say it word for word (never a name brought from elsewhere); then it replaces the words ("his plan" → "Joe Biden's plan"). Otherwise the claim is not self-contained: skipped on the line with the words, never searched (a forced check ends Unverified saying so) | #46 |
| 1c. Claim review | `review.ts` | One prompt per claim (not for forced checks), the mode's model, after breakdown and before any search: its reason, the kind of statement (checkable fact, opinion, value judgement, hyperbole, prediction, promise, too vague, trivially true) and any words the claim never names. A review that fails twice keeps its claim. Measured by `pnpm eval:review` (docs/quality-gate.md) | #46 |
| 1b. Speaker gate | `speaker.ts` | When the title and channel name exactly one person (`pageSpeaker`; their longest form from the description too on the device), that person is the speaker of every claim, "I", "we" and "my administration" included, with or without voices, unless breakdown's `people_named` shows the title or channel naming someone else (names it lists that aren't written there don't count). Otherwise it trusts breakdown's speaker only if its surname is written in the title or channel (or, on the device, the description) and those details name no one else, by breakdown's `people_named` or by the names found here; a known speaker (the viewer's answer, or a named voice) wins. A claim that depends on the speaker with none settled gets `whoSaid` (the names on the page and any the viewer gave this session) and ends Unverified ("Can’t tell who “I” refers to, so this wasn’t checked.") with no search or verdict. | 2. Search | `search.ts` | Runs the two queries through `SearchProvider`; returns one `ResultSet` per query | #29 (classify results) |
| 2b. Balancing | `balance.ts` | If every rated source in the would-be top 5 is on one side (L/LC or RC/R; Center, primary, pro-science and unrated have no side), one more search: the fact query limited with `site:` to up to 4 Center and 4 other-side outlets from a bundled list, each placed by the ratings data and used only if it counts in full. Evidence | `evidence.ts` | Cleans each result's link (`../sources/links.ts`) and classifies it by its final domain (`../sources/`), marks professional fact-checks, drops excluded and user-generated ones, sets partisan ones aside as context (up to 3), then the top 5 at 400 chars: full weight first, alternating between sets (fact, claim, fact…) within each weight, duplicates dropped | |

| Sequencing | `pipeline.ts` | Runs 1–5 (1, 1a, 1a′ and 1c as `findClaims`, which `pnpm eval:review` runs too), reports card stages (`breakdown` → `search` → `weighing` → done), applies the failure policy. `{ forced: true }` tags the cards and, if breakdown finds no claim, checks the words as said, so a forced check always ends in a label. Names each premise's kind (`premiseKind`) from the skipped part with the same words. The judged-as-of date is the page's `recordedOn` when it's a valid date no later than today, else today (`judgedAsOfBasis` says which) | |

**Who said it.** `speaker-answer` on a card re-checks that card, and any other card from the same sentence still asking, from breakdown on with `{ name, from: 'viewer' }`; the card keeps its id and then shows "Said by <name>". An answer to a card that isn't asking is ignored, and Clear now forgets the waiting cards. A later claim asks again: nothing assumes the next sentence has the same speaker. `checkSentence`'s `options.speaker` carries a speaker the session already knows (a named voice): breakdown is told, and no claim asks.

**Voice separation** (`voice-book.ts` in the session; `src/audio/voice-clusters.ts` and `src/models/tasks/voice-separation.ts` below it). Voices are told apart while the transcript comes from on-device speech-to-text, or once the viewer chooses "Tell voices apart for this video" on a "Who said this?" card (for this page only), and only with `deps.separatesVoices`. A line gets a voice from its on-device segment's tag, or, for a caption, from the `voices` turns at its time; a check whose line has no voice yet waits for its audio to be separated, up to `VOICE_WAIT_MS` (15 s), then goes on without one. Each voice gets a letter the first time a line is tagged with it. A sentence from a named voice is checked with that speaker (`from: 'voice'`). On a page whose title and channel name one person, voices are never asked about: that person is the speaker (speaker gate). Otherwise the first sentence from a new voice that holds a claim asks "Who is this?" on its first card (once per voice; a concurrent sentence asks "Who said this?" instead); its claims that depend on the speaker wait, Unverified, for that answer. Naming the voice re-checks every card of it still waiting for a speaker and labels the rest; giving a name another voice already has merges them (`Voice.sameAs`, and the offscreen document merges their voiceprints); Skip turns the waiting claims into "Who said this?" and the voice isn't asked again. The worker's own merges (`voices.merged`) are followed too, except between two voices the viewer named differently. A new page or Clear now forgets the voices. Only names leave the device: never audio, voiceprints or voice ids.

**Heard again.** A sentence whose words nearly all match one already sent to the checks within 20 s of media time (`repeats.ts`) isn't checked again: a replay or seek back (the on-device transcript has no cue ids to spot those by), or captions and the on-device transcript both giving the same speech. One claim makes one card. Clear now and a new page forget them.

**Forced checks.** `force-check` on a line checks that line's skipped words (or the whole line if nothing on it was skipped, or if the claim review dropped a claim from it) with ~30 s of earlier lines as context, from breakdown on, past the filter. Each line can be forced once, and only while listening.

`mbfc-snapshot.json` is written by `scripts/mbfc-snapshot.ts` on `pnpm install` and in WXT's `build:before` hook, and is gitignored (MBFC's ratings aren't covered by the mbfcext licence). It holds the source repo, pinned commit, file path and raw URL, the commit's date (`snapshotDate`), the file's last upstream change (`dataUpdated`), aliases and the normalised ratings (`b` bias, `r` factual reporting, `u` MBFC page, `n` name). The step only goes to the network when the file is missing or was taken from another commit or file. `SOURCE` in the script picks `csources.json` (the spec's choice, frozen since 2022); switching it to `SOURCES.combined` bundles the daily v5 `combined.json` instead. Bump `COMMIT` to take a newer snapshot.

Cards carry, for each evidence source, its `rating` (`primary`, `mbfc` with bias, reliability, name and page, or `unrated`) and `weight`, and the verdict's partisan sources in `context`. `sidepanel/SourceList.svelte` renders them: the count across L / LC / C / RC / R plus Primary, then each row's pill, title, domain, stance, reliability note and opened mark, then the context-only rows. A fact-check row is highlighted with "PolitiFact rated this…". Links open in a new tab with `rel="noopener noreferrer"`; a click or middle-click calls `SourceLinks.opened` (`sidepanel/source-links.ts`, a Svelte context `App.svelte` provides), which marks the row at once and sends `source-opened` to the offscreen document, so the mark survives the panel closing.

The LLM and search sit behind two interfaces in `provider.ts`: `JsonModel.generate({name, system, user, schema})` and `SearchProvider.search(query, { sites? })`. Cloud mode implements both with `venice.ts`; local mode implements `JsonModel` with Gemini Nano (`nano.ts`) and `SearchProvider` with the search the viewer chose (`SessionSettings.search`; `searchOf(settings)` in `session.ts`): `tinyfish.ts` or Venice's, made by `SEARCHES[id].create` in `src/session/searches.ts`. That module is the one registry of searches (name, the key each needs, adapter, counter, policy link) and keys (`KEYS`: service, the stop when missing); settings, the session, the first-run page, the counters and the footprint all read it, and `searchFor(mode, search)` / `keyFor(mode, search)` say that cloud mode means the provider's search and key. In local mode only search queries leave the device, and only to that search. Never a quiet switch to another search. `sites` is the balancing search's outlets (`SiteFilter`: Center ones and other-side ones); each search aims at them its own way. Each adapter reports its answered requests as `Usage {kind: 'search', search}`, counted per search (`veniceSearches`, `tinyfishSearches`). Failures are `ProviderError`s with a `kind` (and a `source`, `provider`, `on-device` or `search` (TinyFish: GLOSSARY keeps the provider and the search apart), which only changes the wording, and an optional `why`, the card's wording when the generic one would hide what happened): `key-rejected` (401, or a 402 x402 payment challenge, which Venice sends for a missing or malformed key), `no-credit` (any other 402) and `search-key-rejected` (TinyFish's 401) stop listening; `failed` (anything else, including a reply that breaks its schema or a search that refused) is retried once, then the card ends as Unverified with "This couldn't be checked: …".

`tinyfish.ts`: `GET https://api.search.tinyfish.ai/?query=…&location=US&language=en` with `X-API-Key` (CORS answers `*` and allows `X-API-Key`, so no host permission); the balancing search uses `include_domains` (TinyFish's docs deprecate `site:` for that). 402 (free allowance used up) and 429 (30 a minute) end the card Unverified with their reason. The key check is `GET /usage?limit=1` (it lists past searches instead of running one).

Local mode once also offered DuckDuckGo's results page (no key, an optional host permission); it refused every request from the extension (a bot challenge, then 403s for the whole connection) and was dropped. The measurement is in `docs/quality-gate.md`, "The search comparison". Session tests for local mode's searches: `src/session/search.test.ts` (fakes in `testing/fake-search.ts`).

`nano.ts` (`createNanoModel(LanguageModel, {clock})`): an on-device `JsonModel` (`onDevice: true`, so breakdown and the speaker gate see the description); temperature 0.1 and topK 1 (`NANO_OPTIONS`, also passed to every `availability()` and the download); one session primed per system prompt and a fresh `clone()` for each prompt, destroyed after its one answer (never a follow-up prompt); one prompt at a time; a prompt with no answer in 60 s (`NANO_TIMEOUT_MS`) counts as hung, timed from its clone, so loading the model for a primed session (slow on the first prompt after the download) has its own 3 min limit (`NANO_LOAD_TIMEOUT_MS`). A crash, hang or broken reply throws the primed session away and fails as `failed`, so the pipeline's one retry runs on a rebuilt session, then the card ends "This couldn't be checked: Gemini Nano, the model on this device, failed." Nano gets the schemas with nullable types (`["string","null"]`) narrowed to plain ones (its supported subset is undocumented), and an empty or `"null"` answer there is read back as null. If Chrome refuses a schema (`NotSupportedError` naming the constraint or schema), the adapter steps down once for the rest of the session, to the schema without `enum`/`additionalProperties`; it never prompts without a schema, so if Chrome refuses that too the prompt fails and the card ends as one that couldn't be checked (the steps' parsers check every reply); the real error is logged in the offscreen document's console. The quality gate runs the verdict step on its own as `judgeClaim(createNanoModel(LanguageModel), input)` (`pipeline.ts`: the verdict prompt, one retry, then the consistency rule, the same function every card runs), from an eval-only extension page (`src/entrypoints/eval/`, built only by `wxt build --mode eval`); see `docs/quality-gate.md`.

`venice.ts` holds the provisional model (`PROVISIONAL_MODEL`, a `private`, non-reasoning model with response schemas; `pnpm eval:cloud` picks the real one, and hasn't been run with a key yet), sets `include_venice_system_prompt: false` and web search off, and strips `<strong>` and entities from search snippets. Requests carry the sentence or claim, its ~30 s context, page title and channel, a speaker the page or the viewer named, snippets and the date: never the page URL, the description (or names found only there) or the full transcript. Sentences the claim filter drops are never sent.

The manifest has no host permissions, optional or not (`tests/e2e/manifest.spec.ts` checks it): TinyFish's CORS answers `*` and allows `X-API-Key`, and Venice needs none either: its CORS answers `*`, and Chrome 151 lets the offscreen document read its responses, 401s included, with an `Authorization` header (checked against the real API). If Chrome ever starts enforcing the `Authorization` exclusion from the `Allow-Headers: *` wildcard, the fallback is an optional host permission `https://api.venice.ai/*` requested at key entry; it is not in the manifest today.

## The on-device model worker (`src/models/`)

One module worker, started by the offscreen document (`startModelWorker()` in `client.ts`) and gone when it closes. It runs Transformers.js 4.3.1 on ONNX Runtime from bundled files only:

| File | Job |
|---|---|
| `protocol.ts` | `ModelTasks`: each task's name, input and output. The messages between the document and the worker |
| `client.ts` | `ModelClient.run(task, input, transfer?)` → the task's output. If the worker dies, every pending and later run rejects |
| `worker.ts` | The worker entry: sets up the runtime, then runs each task's handler from its `tasks` table |
| `runtime.ts` | `runtimeFor()`: 4 WASM threads (at most) and WebGPU when `crossOriginIsolated`, 1 thread when not. `configureTransformers()`: remote models off, local models on, `/models/`, `wasmPaths = '/ort/'`, no Cache API copies, and an `env.fetch` that refuses any other origin |
| `tasks/claim-filter.ts` | The claim filter's handler: `sachaljawad/claimbuster-detector` (DistilBERT, 8-bit) on WASM; scores sentences |
| `claim-filter.ts` | The session's `ClaimFilter`, built on the client. `PASS_THRESHOLD` (0.45, tuned by the quality gate) lives here |
| `tasks/speech-to-text.ts` | Speech-to-text: `onnx-community/moonshine-base-ONNX` (Moonshine base, 8-bit encoder and merged decoder) on WASM; 16 kHz mono in, words out, no timestamps |
| `speech-to-text.ts` | The transcriber's `transcribe(samples)`, built on the client; the buffer is transferred, not copied |
| `tasks/voice-separation.ts` | Voice separation's models: `onnx-community/pyannote-segmentation-3.0` (who speaks when, in windows of at most 10 s) and `onnx-community/wespeaker-voxceleb-resnet34-LM` (a 256-number voiceprint per stretch of at least 0.6 s; no-one stretches left out, two-at-once stretches marked `overlap`, which the clustering gives to the closest voice without learning from them), both 8-bit on WASM |
| `voice-separation.ts` | `createVoiceSeparation(models, newId)`, one per tab: runs the task and clusters the voiceprints into voices (`src/audio/voice-clusters.ts`: new voice below 0.4 cosine and only from a 2 s segment, centroids weighted by length, merge above 0.5, as measured in `prototype/local-mode-eval`) |

To add a model (speech-to-text, voice separation): add its task to `ModelTasks`, write `tasks/<name>.ts`, list it in `worker.ts`'s `tasks` (the compiler insists), and give the session a client adapter like `claim-filter.ts`. Send audio as transferables. Transformers.js runs every model call in a realm one at a time, so tasks in one worker queue behind each other; a second worker is the way out if that ever matters.

Bundling:

- `scripts/models.ts` exports the claim filter to ONNX at a pinned Hub revision and quantizes it (`scripts/claim-filter/export.py`, tools pinned in `requirements.txt`, run in a venv at `.cache/model-export/venv`; it needs Python 3.12, or set `PYTHON`; set `CLAIMCATCHER_EXPORT_VENV` to share the venv). The output is byte-identical between runs on macOS arm64 (the sha256 is pinned in the script and reported).
- Moonshine is downloaded from the Hub at a pinned revision, each file checked against a pinned sha256 (`SPEECH_TO_TEXT` in `scripts/models.ts`); only what dtype `q8` loads (about 67 MB). The voice-separation models are downloaded the same way (`SEGMENTATION`, `VOICEPRINTS`; about 8 MB).
- `wxt.config.ts`'s `build:before` hook runs `ensureModels()`, so a build fails if a model is missing and can't be made.
- `modules/bundled-runtime.ts` copies ONNX Runtime's asyncify WASM and loader (from the `onnxruntime-web` Transformers.js depends on) to `/ort/`, and drops the hashed duplicate Vite would emit.
- The worker is an ES module (`vite.worker.format: 'es'` in `wxt.config.ts`), because ONNX Runtime starts its thread workers from `import.meta.url`.

The panel's Full transcript view (`sidepanel/TranscriptView.svelte`) shows each line's time, source and skipped reasons, with "Check this" on hover or keyboard focus; `ViewSwitch.svelte` is the Claims / Full transcript switch with the "N checked · M checking" count.

## Session lifecycle

- **One tab at a time.** A click on a second tab opens the panel there but doesn't start: the worker keeps that tab's id (`switchToTabId`) and the panel asks "Stop listening on “<first tab's title>” and listen here?" (the title comes from the panel's mirror; the worker never stores it). Confirming stops the first session and starts on the second under that click's activeTab grant.
- **Stop.** Capture ends at once (readers and pill get `stop-reading` / `remove-pill`, badge off), the session emits `stopped`, and its checks in flight go on to a label. The offscreen document keeps the stopped session, in memory only, until Clear now, a new session or the browser closing: so a panel closed at Stop (the pill's Stop, a move to another site) shows the session when it opens again, and "Who said this?" / "Who is this?" stay answerable (an answer re-checks the card; nothing new is heard). Forget key and a mode switch send `settings-withdrawn`: the stopped session then sends nothing more and closes its prompts. `session-stopped` (the session stopping itself) names its tab, so a late one can't stop the next session.
- **Navigation** (`tabs.onUpdated` on the live tab). On every update the worker reads the tab: if its URL is hidden, the activeTab grant is gone, so the tab left the origin and listening stops with `left-site`. On `status: 'complete'` with the URL readable it re-attaches: badge back, `page-changed` to the session, reader, audio capture and pill injected again (WXT replaces the old copies). History `pushState` navigations end in `complete` too, so single-page players re-attach. Note the grant is per origin: `www.youtube.com` → `m.youtube.com` counts as another site.
- **Panel closed.** Listening carries on. `sidePanel.onOpened` / `onClosed` (per window) tell the pill when to show; side panel contexts report `windowId: -1` in `runtime.getContexts`, so the open windows are tracked from the events.
- **Listen again** asks the worker to start on the stopped session's tab. A click in the panel grants nothing, so it works only while the icon click's grant lasts; it isn't offered after `left-site`, `tab-closed`, `page-unavailable` or `reopened` (the blocked player's page is open in a new tab). That policy, which stops need the key fixed, and which were a change of settings (mode, search or key, after which the new settings' needs show), is `afterStop(reason)` in `src/session/view.ts`, folded into the stopped status as `status.after`; the panel only displays it.
- **Clear now** goes to the session (so checks in flight can't bring a cleared card back). On a stopped session the offscreen document then sends `session-cleared`, and the worker closes it. If the document is gone anyway, the panel clears its own copy with `clearView`.
- **Nothing about a session is stored.** The transcript, cards and page live in the offscreen document's and panel's memory; `storage.local` holds only settings, `storage.session` only tab and window ids.

## Blocked players

The spec's capture order: the page's media element first, tabCapture for a player that blocks it.

- **Detection** (`page-audio.ts`, in the tab). `captureStream()` throws `SecurityError` for media from another origin without CORS (Granicus) and `NotSupportedError` for DRM; a page with no media of its own but a frame from another origin at least 200×112 px is an embed (`embed`). Each is reported once over the audio port as `capture-failed`. While a blocked player is in the page, its `currentTime` follows every 500 ms (`player-time`).
- **The session** gets `audio-capture {via: 'blocked', why}` from the offscreen document, and the panel shows "This player blocks direct listening".
- **Allow** (`BlockedPlayer.svelte`). Without tabCapture: why, then what Chrome's prompt will say ("Read and change all your data on all websites") before it shows, and Allow, which calls `permissions.request({permissions: ['tabCapture']})` in the click. Chrome adds tabCapture to a tab's grant only at an icon click made while the permission is held, so the page already open can't use it: the panel then offers "Reopen in a new tab at the same moment" (just "Reopen in a new tab" for an embed, whose time can't be read) and says to click the icon there. The worker (`reopen-in-new-tab`) pauses the old video, reads its time, opens the same URL in a new tab beside it, and stops listening with `reopened`; when listening starts on the new tab it seeks there (`reopenedAt` in `storage.session`).
- **With tabCapture held**, the panel gets a stream ID for the tab straight away (`tabCapture.getMediaStreamId({targetTabId})`) and sends it to the offscreen document (`use-tab-stream`), which opens it with `getUserMedia`, plays it back (Chrome stops playing a captured tab's sound to the viewer) and feeds its frames to a transcriber; the session gets `audio-capture {via: 'tab'}` and the notice goes. Then the page's own PCM is ignored (tabCapture hears everything) and only sets the time. The capture survives navigation, so `stop-session` and a new session end it.
- **Why the panel and not the service worker.** In MV3, an ID asked for without `consumerTabId` can be used only in the asking context's process (`tab_capture_api.cc`: `caller_process_id = source_process_id()`). The offscreen document is cross-origin isolated (COEP/COOP), so it runs in another process than the service worker, and the worker's IDs fail there (`AbortError: Error starting tab capture`, Chrome for Testing 151). Extension pages are cross-origin isolated too and share the offscreen document's process, so the panel's IDs work. The panel opens with every icon click; if it's closed when a player blocks, the fallback happens when it opens.
- **Times.** tabCapture has no element clock. `tab-clock.ts` counts its samples from the player's reported time, and takes the player's time again when they differ by over 0.4 s (a seek, a pause). An embed reports nothing, so its lines are timed from when capture began, and Replay can't seek it.
- **Embeds** use tabCapture and the on-device transcript; nothing is injected into the frame and no host permission is asked for. Captions inside them aren't read.
- **Privacy & data** lists tabCapture with Revoke once granted (`welcome/permissions.ts`, from #32).

## Decisions (from code review 1)

Places where the build reads the spec one way on purpose; keep them unless the spec changes.

- **Cost can show one figure.** The footer's cost is a range only where it is estimated. When Venice reports `cost.usd` on every reply, the cost is what was billed, so low and high are the same figure and one figure shows (`src/footprint/estimate.ts`). Exact billing beats an estimated range; energy and carbon stay ranges.
- **"Someone else…" takes free text** on "Who said this?" and "Who is this?". The names on the page are one-tap buttons as the spec asks; a typed name covers a speaker the page doesn't name. It is the viewer's answer, never a guess, and is offered on later prompts in the session.
- **The YouTube and House readers turn captions on**, if they are off, and put the viewer's setting back at Stop (`youtube-reader.ts` presses CC; `house-player.ts` selects CC1 and restores the tracks). Their captions can't be read otherwise, and captions come first.
- **MBFC MOSTLY FACTUAL counts less** (reduced weight, "mostly factual, counts less" to the verdict step). The spec's table names only VERY HIGH / HIGH for full weight and MIXED for reduced; MOSTLY FACTUAL sits between them and is treated with the reduced tier, marked "mostly factual · counts less" on the card.

## Not built yet (hooks for later tickets)

- Wording in the panel exists for `key-rejected`, `no-credit`, `no-key`, `left-site`, `tab-closed`, `page-unavailable` and `reopened`.
- On a `pushState` navigation Chrome sends `complete` before the page changes its title, so the session keeps the old title until the next full page load.
- A blocked player met while the panel is closed (a same-site navigation to it) waits for the panel to open before tabCapture starts.
- Only one media element is captured at a time; another one starting to play takes over. Each re-attach injects the audio capture again; the offscreen document listens only to the tab's newest port.
- Voice separation tags a whole on-device segment (5–15 s) with the voice that spoke most of it: Moonshine has no word timestamps, so a turn that changes inside a piece goes to the majority voice. Caption lines take the voice at their (lag-shifted) start time.
